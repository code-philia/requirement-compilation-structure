# Arco 检索与生成集成计划

目标：组件选择使用可查证的用途资料，实现时能查找准确 API；四个阶段使用同一份组件知识。
保留已有 component/binding、业务需求、后端协议及页面复用逻辑。

## 实现步骤

1. 建立本地组件知识库。覆盖当前允许的组件，记录用途、适用/不适用场景、关键属性、
   交互注意事项、简短例子和官方参考链接。与固定版本组件/回调目录校验一致。
2. 增加 BM25 组件检索。按需求选择候选，已选组件和复用页面组件优先保留。
   UI/Trigger 设计额外开放 component 类型的 context_request，支持搜索和按 ID 查阅。
3. 增加只读 list_files/search_files。支持 glob 文件过滤、字面文本搜索、行号、
   有界上下文及分页；只搜索任务已授权文件，不执行 shell，不扩大写权限。
   默认不改变其他智能体工具，前端任务显式启用。
4. 接入 UI 实现和 Trigger 实现。注入选定组件资料、只读指南、可搜索 API 声明；
   更新智能体循环处理搜索结果，并让修复过程保留相同能力。
5. 发布和记录。生成应用保留组件知识文件和类型声明，记录每阶段检索命中；
   补充使用说明和边界。遵照仓库 AGENTS.md，不新增或运行测试；只检查语法、
   编译器导入及变更格式。完整模型生成不属于本次验证。

## 数据流

需求/已有页面 → BM25 组件候选 → UI component 选择 → UI 实现查阅文档/API
→ Trigger callback 选择 → Trigger 实现/修复查阅同一套文档/API。

页面 RAG 仍用于页面复用，组件 RAG 单独负责组件用途。BM25 是词法检索，
无匹配不证明没有可用组件；模型可查询完整组件索引。类型声明仍以安装的固定
版本为准，用途指南不冒充官网完整镜像。
