请制作一个“建筑日照分析模拟器”：用真正的 Three.js 三维渲染，展示太阳位置、建筑遮挡和地面日照状态，并支持直观的参数调整和动画演示。

【交付格式与本地环境】
只输出完整 HTML，从 <!doctype html> 到 </html>，不要加 Markdown 围栏或解释。CSS 和业务 JavaScript 全部内联。
平台已在本机提供 Three.js 和 OrbitControls 的合并运行库，先同步加载：
<script src="/api/course/vendor/three.js"></script>
然后使用普通脚本中的全局 THREE 与 THREE.OrbitControls，不再 import three，不使用模块脚本、importmap、CDN、React 或其他外部脚本。不请求外部模型、纹理、字体或图片；可以自行生成几何体、材质和 CanvasTexture。
应用在当前平台的本地 HTTP 预览中运行，不依赖外部接口。若 WebGL 不可用，页面应显示清楚的错误信息，而不是空白。

【一、基础三维场景】
整体要求是明亮的白色背景：页面背景与三维画布背景均以白色为底，不使用深色主题。地面可用接近白色的浅灰区分范围，用材质、细边线、阴影和适量强调色组织层次。
1. 使用真正的三维建筑、地面和光照，不能用静态图片、CSS立方体或二维透视图代替主体。支持 OrbitControls 拖动旋转、平移和缩放，初始为能看清建筑群及阴影的斜俯视角，不能转到地面以下。
2. 地面为240×240米，一世界单位为一米；坐标约定为+X东、+Y上、+Z北。显示方位、网格和建筑编号。
3. 默认四栋建筑均底部贴地，宽16米、进深14米。默认中心平面坐标(x,z)与高度：A=(-22,-12)，高24米；B=(18,-12)，高36米；C=(-20,20)，高18米；D=(20,22)，高30米。建筑中心y=高度/2。
4. 太阳使用 DirectionalLight，配合适量环境光。启用建筑投影和地面接影，使用真实动态阴影，不用固定的暗色图形伪造。合理配置阴影范围、分辨率和bias，使阴影清楚且不过度闪烁。
5. 默认建筑可采用长方体作为分析主体，但应有立面、窗格、楼层、入口或屋顶等细节；选中状态和文字清楚可读。在明亮白色背景下，建筑配色、材质、构图、面板布局和精细表现由你设计。

【二、统一的日照计算】
按以下简化数学模型实现，使不同作品的基础结果可以比较：
- 时间t为07:00—17:00的示意太阳时，默认12:00，滑块至少精确到5分钟。
- 季节为冬季、春秋、夏季；正午太阳高度角H分别为32°、55°、78°，默认春秋。
- 令θ=π×(t-6)/12，H换算成弧度。指向太阳的单位方向为：
  sunDir=(cosθ, sinθ×sinH, -sinθ×cosH)。
- 太阳高度角α=asin(sunDir.y)，以度显示。太阳光源位于sunDir×200，目标为原点。太阳标记、轨迹、实际光照与分析射线必须使用同一方向。
- 太阳轨迹按同一公式采样07:00—17:00。上午太阳在东侧，正午在南侧，下午在西侧，阴影方向随之变化。
- 选中建筑的理论影长=建筑高度/tanα，单位米，保留一位小数。这是水平地面上孤立竖直物体的理论值，不需要根据阴影图像估算。
- 在说明区域简要交代采用的模型与单位，不调用外部天文服务或把示意时间冒充真实城市日期。

【三、即时地面日照分析】
1. 在x、z均为-50到50米的区域，生成15×15个均匀采样点；它们固定在世界坐标中，不随建筑间距缩放。
2. 落在建筑底面范围内的点排除，不计入有效样本。
3. 从每个有效点的(x,0.05,z)沿sunDir向太阳发射射线。与任一建筑主体相交则遮阴，否则受光。只检测建筑主体，不把地面、窗格、标签或太阳标记误当遮挡物。
4. 用不同颜色显示受光与遮阴点，并提供图例。显示“受光点数/有效采样点数”及“当前地面日照率=受光点数/有效采样点数×100%”，保留一位小数。
5. 时间、季节、建筑高度或间距改变后，阴影与采样结果同步更新。动画中可适当降低采样计算频率以保持顺滑，暂停后修改参数仍需更新。
禁止用随机数、预填百分比或无关的装饰动画代替真实遮挡判断。

【四、必须工作的交互与动画】
1. 时间滑块：07:00—17:00，并显示HH:MM；拖动后立即更新太阳、阴影与指标。
2. 播放/暂停和0.5×、1×、2×速度：1×时完整07:00—17:00过程约60个现实秒；到17:00后暂停，再次播放从07:00开始。默认暂停，继续时不补算暂停期间的现实时间。
3. 暂停只停止太阳时间推进，仍可操作相机和参数。播放不强制旋转相机。
4. 季节选择：保留当前时间、建筑参数和视角，更新太阳轨迹、光照与分析。
5. 点击建筑或从建筑选择框选中（初始A/B/C/D，新增后同步更新列表）；详情显示编号、高度、平面坐标与理论影长。相机拖动不应被误判为建筑点击。
6. 高度滑块：10—60米，步长1米，只修改选中建筑；同步调整中心y，保持贴地，其他建筑不变。
7. 建筑间距倍率：0.7—1.6，步长0.1，默认1.0。各建筑x、z按默认坐标乘倍率计算，尺寸不变；不能反复叠乘造成位置漂移。
8. 提供总览、俯视、南侧三个视角，以及太阳标记、轨迹、网格和采样点的显示开关。显示开关不改变计算结果。视角过渡自然，用户拖动时停止未完成的自动过渡。
9. 重置：恢复12:00、春秋、暂停、1×速度、间距1.0、四栋默认高度、选中A和初始总览视角，立即刷新全部指标。连续重置不产生重复对象、重复监听器或多个动画循环。

【五、展示与运行质量】
主要指标应能直接看见：当前时间、季节、太阳高度角、选中建筑高度与理论影长、地面日照率及受光点数。数字与画面来自同一状态，不能各自变化。
请在建筑分析工具的专业感、视觉精细度和操作流畅度上做出设计：界面分组清楚，场景有层次，选中状态、光影和辅助信息协调。不要机械堆满同样的卡片，也不要让装饰遮挡分析内容。
1440×900和390×844下都能操作，无页面横向溢出；根据画布容器更新渲染尺寸和camera.aspect。像素比最多1.5，阴影与建筑细节数量合理，优先保持交互顺滑。
使用一个requestAnimationFrame主循环；控件有可读标签、键盘焦点和正确状态；尊重减少动态效果偏好。不使用未提供的插件，不留TODO、占位按钮或伪造的统计。

【六、开放挑战：渲染表现与建筑编辑】
基础日照功能按前面的明确规则实现。扩展重点放在场景质感与建筑编辑，不需要双方案保存、切换或对比，也不要求全天累计分析。

必须能新增建筑，并在选中后移动建筑位置；添加与移动的具体交互由你设计，可以结合三维画布、属性面板或其他直观方式。新增建筑要有独立编号、合理尺寸并贴地，能继续被选择和编辑。移动后，建筑、细节、选中轮廓、阴影和即时日照采样应保持一致，不能只移动一个外壳或改动输入框。编辑时不要和相机旋转相互抢操作。

以下方向只给出目标，不规定具体做法，请自主选择并深化：
- 渲染品质：更丰富的建筑类型和立面细节，玻璃、金属或混凝土的材质差异，合理的光影、接触感、色彩与层次，让白色背景下的场景精致且有建筑作品的质感。
- 场地表达：道路、步行空间、绿化、小尺度设施、尺度参照或标注，与建筑群形成有组织的空间，而不是孤立地摆放几个盒子。
- 编辑体验：建筑复制、删除、尺寸修改、旋转、拖动、吸附、尺寸辅助或撤销重做。重点是操作直观、反馈及时、状态收得住，不必机械堆砌所有按钮。
- 观察与动画：聚焦选中建筑、自然的视角过渡、清晰的选中与编辑反馈，以及参数变化时容易理解的联动展示。
- 表达与性能：专业而简洁的分析界面，可考虑渲染质量选项，让精细表现与交互流畅度取得平衡。

建筑新增、移动、旋转或删除后，遮挡判断和有效样本必须对应实际建筑主体及位置，不能继续使用默认四栋建筑的旧数据；如支持旋转，也不能把轴对齐包围盒当作精确底面。间距操作与编辑后的布局如何配合可自行设计，但不能无提示覆盖用户的位置编辑。默认间距的基础核对在未编辑布局下进行。
重置时恢复初始四栋建筑，移除新增建筑并恢复移动过的位置及朝向，所有显示与计算一并更新。扩展一旦展示就应实际可用，不能用伪造数据、占位操作或视觉特效替代正确联动。请优先完成可靠的新增与移动，再用设计细节体现你的能力。

- 新增或移动建筑后，编号、选择、阴影、采样排除及日照率按实际布局更新，原有建筑不被意外改变。
